# Updating the existing private preview when local secret files are lost

This update-only path retains the original write-only provider secrets. It does not recover their values or prove their equality across Workers. The committed prior deployment and unchanged provider versions establish the ownership chain; post-deployment checks must still verify runtime behavior. It does not authorize a deployment, public URL, additional spend, or any production effect.

Collect fresh read-only account quota evidence in `cloudflare-app-preflight.json` and provider settings in a mode-600 JSON file in an owned, mode-700 directory outside the checkout. Set `HIVE_PREVIEW_PROVIDER_EVIDENCE_FILE` to its absolute path. Its shape is `{schemaVersion:1, observedAt, accountId, targets:[...]}`. Each target contains `name`, `exists`, `tag`, `createdOn`, `deploymentId`, `versionId`, `publicState:{enabled,previews_enabled}`, and `bindings`, an array of `{name,type}` entries from the actual current version. Include the `value` returned by the provider for the six public issuer variables: `HIVE_CODEX_ISSUER_KEY_ID`, `HIVE_WORKSPACE_READ_ISSUER_KEY_ID`, `HIVE_CODEX_HIVE_ORIGIN`, `HIVE_WORKSPACE_READ_HIVE_ORIGIN`, `HIVE_CODEX_SOFTWARE_TEMPLATE_IDS`, and `HIVE_CODEX_ISSUER_PUBLIC_KEY`. Never include secret values. The operator must obtain these fields directly from provider read-only responses; the local file is an operator assertion, not a signed provider attestation. Evidence must be at most 60 seconds old each time it is consumed.

After committing source, completing the existing local proof, and building its matching artifact, prepare with `--update-preview --inherit-preview-secrets --native-gateway-candidate --workspace-projects-candidate`. The resulting private app secrets file contains only newly generated `PREVIEW_BEARER` and `PREVIEW_COOKIE_SECRET`; the auth file is empty. Wrangler's additive `--secrets-file` behavior retains omitted secrets. The original preview identity ID and issuer public key are pinned to the prior deployment evidence. Private gate rotation invalidates prior preview sessions.

Before each authorized upload, refresh and independently inspect provider evidence and run the existing prepared deploy command. Upload auth first. After provider readback confirms its new deployment/version and prepared source, create an operator-recorded mode-600 receipt in a private directory, set `HIVE_PREVIEW_FIRST_UPLOAD_RECEIPT_FILE` to its absolute path, and then upload app. Receipt fields are `{runId,sourceRevision,kind:"auth",previousDeploymentId,previousVersionId,deploymentId,versionId}`, with `runId` and `sourceRevision` copied from the prepared manifest and all IDs verified from provider readback. For the second upload the fresh provider evidence must show that receipt's exact auth deployment/version and the unchanged original app version. This operator receipt is not a provider signature; stop and investigate any ambiguous or failed upload rather than inventing a successful receipt. API readback and upload are not atomic, so operator ownership and immediate recheck remain necessary. Revalidate the new deployments, private URL state, bindings, and guarded application behavior afterward.
