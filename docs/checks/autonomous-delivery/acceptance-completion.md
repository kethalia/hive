# Controller completion after independent verification

This default-off installed path closes the normal end-of-turn gap: when the manager published a candidate and ended without reporting success, the installed controller waits for independent semantic review and all mandatory repository gates. It then creates a factual successful report and uses the existing protected source-application flow. A final step needs no extra manager inference merely to author a report. Intermediate steps retain the same guarded continuation rules.

`complete_verified` is a fixed signed registered-host action, absent from model tools. The server rechecks owner, current registration/native lifetime, guarded producer, immutable intent/plan/policy, current attempt/root/cursor/sequence, accepted source, valid attempt lease, and fresh (30-second) terminal/cohort facts. Every recorded child in the manager binding must match a completed signed native observation. Unknown work remains a hold; this is not kernel-process quiescence. Activation/production steps and change/migration requirements cannot use this controller path.

The host obtains a fresh full native boundary after the evaluator archives its thread, and an authenticated native-spool snapshot with no unacknowledged source events or unknown inputs. The factual snapshot is separate from source application's existing result requirement. A scoped server receipt must be imported before metadata application is possible. The factory and spool reject changed scope or journal bytes after the server await. Tenant/native revocation remains enforced. No input or physical-writer fence is cleared by a completion receipt.

The server authenticates all supplied independent evidence and requires every repository gate and semantic criterion. The real composed test exposed a pre-existing mutual-rejection bug: repository coverage checked semantic rows against a GitHub-only producer list, while semantic coverage checked GitHub rows against a semantic-only list. Each already-authenticated family is now used for its own required coverage checks. No group, criterion or freshness/provenance check was removed. The final shared completion check still validates the combined trusted evidence set.

`completeStepInTransaction` extracts the existing repository completion transaction unchanged in behavior. Model input still uses its original difficulty enum. Only this controller-authored report can use `difficulty: unknown`; its text describes observed verification, makes no manager narrative or correctness guarantee, and references the actual source and evidence IDs. The step/report/outbox and immutable controller receipt commit atomically. Concurrent and exact replay return the original receipt, without another report. Replay requires fresh matching scope and current authority. Ambiguous transport/journal outcomes remain held rather than guessing success or repeating inference. The controller does not clear a user pause; it requires an unpaused task, and the original physical writer is retained.

## Evidence and limits

`completion-local/result.json` binds the exact reviewed sources. Validation includes 133 actual-native/runtime checks, 26 acceptance/repair/review PostgreSQL checks (11 completion cases), 44 repository/policy/manager/progression checks, typecheck and formatting. The native proof uses pinned Codex 0.165.0 and a local canned Responses server: failed B → same-step repair on the same manager thread → candidate C → a separate controller-created evaluator passes → signed GitHub challenge/snapshot ingestion → full real repository/semantic policy → controller completion. The report has unknown difficulty and the writer remains held.

Provider snapshots and object storage are explicit local doubles. Initial enrollment/publication, child observation facts and protected-application receipt in that native proof are also explicit fixture authority, not a claim of installed account-backed end-to-end completion. Actual input/application, observer and isolated runtime components have their separate prior proofs. No account inference, GitHub writes, merge, deployment, production activation or cleanup authority is claimed here.

The initial full-policy failure is retained in `completion-local/full-policy-first-failure.log`. The fixture was stopped and its task-owned scratch independently checked and removed. An earlier broad test command used a rejected database name; its pre-test failure is preserved. Correctly named fresh33 and corrected populated31→frozen32→33 fixtures then passed. Old applied migration checksums and earlier repair evidence were not rewritten.
