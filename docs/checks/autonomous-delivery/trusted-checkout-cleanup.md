# Trusted managed checkout cleanup

The existing signed guardian completion path now connects its private cleanup adapter after independent production acceptance, completion-purpose physical tree closure, session/source preservation, lease release and archive acknowledgement. It uses the existing issuer and route; it creates no cleanup endpoint, model tool, publisher, credential or database table. Standalone tasks retain the same immutable closure facts in existing delivery events. Epic tasks retain the existing writer release and epic capability checks.

The cleanup token has a separate `hive-project-cleanup-v1` signature domain. It binds the exact owner, workspace, current build/lifetime/config, historical completion barrier/tree, repository/source, checkout incarnation and physical identities, lease generation, production acceptance events and approved repository policy. Preservation requires a fresh full R2 content read with its actual upload `version`; a content digest or ETag cannot replace that version. Bucket retention/IAM remains a deployment requirement, rather than a claim established by an upload version.

Current home-volume evidence comes from fresh Coder resources for the exact connected agent-bearing deployment and immutable current build/template version. Its complete PVC and actual HOME mount tuple, resource identity and digest enter the signed claims and retained cleanup receipt. This supports later empty-root revalidation without accepting guest-provided volume claims. It supplies no permission to bypass physical consumer checks.

The installed private helper verifies issuer signature, scope and deadline. It retains the project directory, session descriptors and evidence, and removes only the originally created managed checkout after clean Git, remote preservation, exact inode, no nested repository/mount/link, and strict no-consumer checks. A live sealed outer guardian supplies only independently verified process-construction facts through the reviewed installed observer. A historical closed guardian requires its exact authenticated completion receipt. Neither construction facts nor unstarted-recovery permissions authorize cleanup.

A signed permit lasts at most 45 seconds, also bounded by the signed request and production policy. If it expires before deletion begins, a fresh locked inspection can report `not_started` for the same incarnation and request. The server then appends a new immutable grant version after repeating all gates and the full object read. Each version has its own authorization ID. A signed factual status action returns only the exact retained token, including its original expiry, or confirms that no initial token exists; it never mints authority. Lost refresh acknowledgements use that readback before another locked inspection, so an old inspection cannot trap retries forever. Cleanup transport uses the existing 30-second closure budget; actual tokens remain capped by the request deadline. Inspection/permit ACK loss replays the same version. A pending deletion, active helper, completed marker or changed binding cannot obtain this refresh. Grant history is bounded to 16 versions.

The local HMAC marker is durable before removal. If deletion completed but its final receipt or ACK was lost, exact historical evidence can complete the factual receipt without deleting again, including after permit expiry. A dangling symlink is never absence. After a crash, removal holds whenever full physical/Git validation cannot be re-established; ordinary prepare/reuse also holds while the deletion marker is pending. An unchanged checkout can proceed only after all original validations pass again. The implementation does not weaken source checks to finish an unverified partial tree.

## Validation and limits

Owned local PostgreSQL tests exercise actual production claims, independent acceptance results, completion and physical-receipt persistence, R2 full-content/version checks, standalone/epic closure, maintenance actor history, concurrent issuance, post-SQL expiry rollback, unused-permit refresh and idempotent acknowledgement. Provider, kernel and model observations are explicit fixture doubles. A composed test passes the actual signed permit to the installed OpenSSL verifier and deletion code against a real temporary Git checkout, rejecting wrong-domain/signature/expiry/build first, then proving project/evidence preservation and exact replay. Python tests cover partial removal, completion crash, symlink replacement and unchanged generic preparation holds. The successor reader has existing actual-PG retirement/enrollment tests plus a closure caller regression; these are compositional evidence, not a claim that an unused-retirement-to-production pilot has run.

No live checkout was removed and no production capability was enabled by this source change. Final production cutover, actual object retention, real accepted workload semantics and the live full-flow cleanup acceptance remain owner-controlled release gates. Generated packages are synchronized only after the reviewed upstream observer source is integrated.
