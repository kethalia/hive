# Source publication transport (in progress; disabled)

This adds no live provider access, producer admission, deployment configuration or cloud writes. Source execution, manager execution and preview transport remain disabled. A registered host signature is insufficient without the independent finalized OPEN guardian admission store. No local HMAC journal or fixture receipt substitutes for that authority.

## Broker wire and phase ordering

The exact strict schemas and signature helper are in `src/lib/delivery/source-transport-contracts.ts`. All three POST paths use the host Ed25519 registration key and domain `hive-source-transport-v1`, method, fixed path and canonical unsigned JSON, separated by newline. The common envelope is `schemaVersion:1`, `action:publish_source_revision`, registration/server/manager-thread IDs, immutable six-field `checkoutBinding`, current `sourceContext` when advanced, task/step/attempt IDs, issuedAt/expiresAt (milliseconds, maximum 60 seconds) and proof. Browser origins and query strings are rejected. No model supplies a producer, policy, passed evidence or acceptance authority.

1. Read server-owned policy using `/api/delivery/source-publication/policy`: common envelope plus requestId and operationId. The response derives operationId, parentSha, sourceContext when present, sourceVersion, repository/account identity, fullName, fixed branch, policy, policyDigest and expiresAt. Policy includes version, baseBranch, authorName, authorEmail, allowedPrefixes and file/count/byte limits. Read this before sealing. The broker captures commit date once in its private operation journal and uses only this pinned author/base/path policy. This read is not an effect grant.
2. Seal local raw-byte manifest/tree/commit in the protected broker. Source files can change afterward without changing the sealed bytes. No provider effects precede a grant.
3. Request `/api/delivery/source-publication/challenge`: common envelope plus requestId, operationId, policyDigest, target `{headSha,treeSha,manifestDigest}` and canonical manifest. Manifest files are sorted records `{path,contentDigest,size,mode,blobSha}`; deletions are sorted paths. The issuer checks current server policy digest, path/type/byte restrictions and exact manifest digest before granting effects. The grant additionally pins current source/cursor/native sequence, physical writer lease, independently persisted producer admission/generations/incarnation, provider identity, fixed branch, policy and one-use nonce. Each task has a bounded preview grant budget; expiration never silently extends an existing grant.
4. Execute only fixed GitHub commit/tree/blob, create-only ref and exact draft PR operations using the sealed bytes and grant. Exact readbacks must match parent/head/tree, repository/account, branch, base and PR identities. Lost acknowledgments retain exact journal bytes; mismatches hold.
5. POST `/api/delivery/source-publication`: common envelope plus challengeId, nonce and readback. Readback contains observedAt, repository/account/fullName, manifest, commit `{sha,treeSha,parentSha}`, reference `{name,sha,type:commit}` and pullRequest `{id,number,headRepositoryId,baseRepositoryId,headRef,headSha,baseRef,state:open,draft}`. The signed envelope never carries credentials or arbitrary response headers. Retain exact immutable request bytes for retry.

A preflight transaction reserves the exact wire digest and planned object key/size in an append-only event before any upload. This is an unverified reservation, not acceptance or nonce consumption. Changed retry bytes cannot create a second artifact under the same grant; failed final authorization retains auditable orphan provenance. The server archives canonical signed grant/envelope bytes (at most 96KiB) through conditional R2 create and full bounded digest/size readback. A second transaction revalidates independent producer authority, active registration, policy, task/source/attempt/lease and consumes the nonce atomically with source acceptance or a committed reconciliation hold. The append-only receipt retains the object key, size and digest. Exact consumed-wire replay can return its original source receipt; it never grants native execution. Fresh, changed or expired replay fails closed.

## Remaining integration

The guardian store is developed separately; a production factory must call its finalized-admission lock under slot/registration → runtime → admission → intent → manager binding → task ordering. Bootstrap/preparation state is not producer authority. Policy is deployment/controller configuration, never request or repository content. Actual protected Python broker/provider wiring and read-only Git metadata projection are separate reviewed changes. Draft PR recording does not make draft PRs eligible for final checks/review. Existing GitHub acceptance still applies.

R2 writes can finish after a timeout, revocation or barrier closure. An unsuccessful final authorization can therefore leave an immutable orphan object and incur bounded operations; this transport does not delete it or promise rollback of external effects. Continuous polling, cleanup, production migrations, preview gate exceptions and all production activation remain outside this slice.

## Trusted host signing adapter

The installed adapter derives registration/server/root and immutable checkout scope from trusted supervisor callbacks, and derives current task/step/attempt/source context from its acknowledged journal and authoritative server readback. The model supplies only requested file paths/deletions and commit/PR messages. It cannot select endpoints, repository identities, author/base/path policy, current source, nonce, producer digest or signing key. The broker returns only bounded sealed metadata to the outer signer; raw source bytes and provider credentials remain private.

Use the exact `sourceTransportProofPayload` canonicalization helper outside the native namespace. Before each fixed provider network operation, a trusted callback may re-POST the original stored signed challenge and require the identical still-live grant; this revalidates current admission/policy/source and never extends expiry. Unknown outcomes retain exact sealed bytes and request journals. After complete provider readbacks, journal the final signed publication bytes once, then retry those bytes unchanged. Exact consumed replay preserves the original receipt even after its readback freshness window; capability expiry, current registration, policy and independent admission checks still apply. A timed-out/expired grant or unavailable current authority yields a hold, not new effects or inferred success.

## Local validation and trust limits

`source-transport-local/tests.txt` records 48 focused source/progression/protocol/route/policy checks on the preserved schema23 fixture. `source-transport-local/r2.json` records actual local workerd R2 conditional creation, streamed integrity readback, exact retries, restart persistence and adversarial corruption, composed with the 12 protocol PostgreSQL cases. Those protocol cases deliberately inject their admission callback; no cloud bucket or provider operation occurs.

`source-guardian.integration.test.ts` separately drives the real guardian persistence lifecycle through the shared staged `nativeFixture` hook, then exercises source issuance/publication under `lockProducerAdmission`. It verifies original receipt replay, persisted producer revocation after upload, no nonce/source advancement on rejection, retained unverified object reservation, and preserved physical writer ownership. Its owner authorization, package pins, checkout inode metadata, native events and provider readback are explicit local fixtures. This proves database phase composition and rejection behavior; it does not prove real workspace attestation, native namespace isolation, installed broker composition, Coder cryptographic bootstrap routes or GitHub effects. Guardian-store development remains separately reviewed.

The task grant limit is 32 and the operation limit is three grants. A repeated original challenge reads back its existing unexpired grant and consumes no new budget. These are bounded preview limits; continuous polling, automatic expiry extension, changing bytes under an existing reservation and automatic grant retirement are not enabled.

The final transport-only schema24 run records 61 PostgreSQL/unit checks; later publisher signing tests are intentionally excluded from this checkpoint. `typecheck-draft.txt` retains an intermediate concurrent fixture typing failure, while `typecheck.txt` is the later passing check.
