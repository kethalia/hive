Old claims remain provenance, not runnable aliases. A completed task receives no new input. A successful step on an unfinished task may progress through normal claim/source/lease/evidence gates. An unresolved prior effect, expired writer/checkout lease, source drift, unknown history or lost input ACK holds; unknown effects are never automatically repeated. A lost input ACK is reconciled through a bounded native history read or remains held.

Physical parking does not settle an external effect. Owner resume, final epoch/unpause and the first fresh claim recheck the existing release action and source-publication ledgers under task locks. Only factual observed/canceled outcomes or an existing matching publication-consumption receipt clear this barrier; no retry or provider absence is inferred. Exact authenticated report/GET reconciliation for a previously started automatic database action is a separate combined-source integration gate, never new dispatch or SQL authority while paused.

While maintenance is pending, account status is cached only (no CLI spawn, credential read/refresh or auth lock); an exact existing login cancellation remains possible. Credential mutation is allowed only after actual managed tree exit. Existing shared-native/exclusive-auth locking remains in force. This does not terminate unmanaged user CLI processes or revoke provider-global credentials.
