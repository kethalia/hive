# Fixed factual source state client (inert)

`delivery-source-state-client.mjs` exposes `createDeliverySourceStateClient` only through explicit trusted composition. It has no default host/controller wiring or new flag activation. Configuration supplies the fixed HTTPS Hive origin, private host key, trusted currentContext and independently verified current metadata/namespace callback. Model query fields cannot replace the site, task for apply, policy, producer or physical writer.

`readForApply(thread,{operationId,revisionId?})` derives the current task and immutable owner/manager/registration/physical checkout scope. It requires an exactly scoped fresh response with `isCurrent:true`, identical accepted/current source context and head, matching metadata/admission tuple, and both authority flags false. It supplies factual input to a separately authorized local apply operation. It grants no input reservation, metadata-write permission, native execution or publication.

`readHistorical(thread,{taskId,operationId,revisionId?})` can query an owned old task on the same held physical binding. It accepts truthful historical/current distinction and retains false permissions. Historical facts cannot pass the apply-facing current-head check. The independent apply adapter must additionally validate the local predecessor/version CAS, protected Git/index identity and its own project input barrier/reservation before mutation.

Every request uses the fixed POST `/api/delivery/source-publication/state`, a new request ID and the separate read action/signature domain. There is no cached-success path, old publication nonce, cookie/master bearer, arbitrary endpoint, worker command, R2 access or GitHub operation. Request/response sizes, read counts, total deadline and cancellation are bounded. Client close aborts pending authority/network reads. Errors expose fixed source-state codes, not response bodies or callback secrets.

Before and after HTTP, the client checks trusted current scope and the full independent runtime/admission ID/generation/producer/incarnation/barrier tuple, metadata pins/evidence/policy/namespace digests, and actual checkout/Git inode pins as decimal BigInt strings. The metadata callback must prove the registered installed namespace inventory and current persisted authority; local inode equality alone is insufficient. The opaque metadata evidence digest is preserved rather than recomputed from pins alone.

`source-state-client-local` records 11 Node cases and one cross-server signing-byte test. Network/metadata callbacks are explicit local test doubles. Tests cover current and historical behavior, request-scope override rejection, foreign/mutated provenance, source inconsistency, metadata drift, freshness limits, sanitized errors, stalled body/cancellation and close. Actual database/guardian and61-second expiry evidence is recorded separately in `source-state-local`. No installed factory, live provider, cloud mutation or production activation is claimed.
