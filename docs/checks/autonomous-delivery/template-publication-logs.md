# Bounded authenticated logs and terminal notices

This schema-29 slice completes the portable publisher's detailed-log and terminal-notice implementation paths. Activation/cutover remains disabled and requires the separately reviewed runtime/provider plan. No real provider log, subscription delivery, credential rotation or cloud resource is used by this slice's tests.

## Human log view

`GET /api/templates/<known>/push/<job UUID>/logs?after=<canonical int64>` requires a current authenticated browser session and an exact owner/catalog/job match. The route rejects extra/duplicate parameters, cross-origin reads and all other methods. It has a separate default-off `HIVE_TEMPLATE_LOG_VIEW_ENABLED` gate and normal preview/browser authorization; it adds no host-callback exception. There is no caller URL, version/file/import ID, actor, policy or artifact input.

The service uses one captured subject-verified Coder credential and a fixed configured origin. Only GET requests occur. Remote organization, version, file, import job, creator, initiating user, name and artifact marker must match the immutable publication record. Identity/permission is checked again after buffering, and the current Hive owner/Coder identity and session are reauthorized before returning. A new valid session for the same owner can read historical work. Original unattached create imports remain exact-version factual reads even if an unknown creation response later attached them; this never binds a target UUID, completes a publication or grants execution.

The pinned non-follow log API accepts `after` but does not implement a usable row limit. The new reader incrementally consumes its HTTP JSON array, not WebSocket messages or an unbounded `response.json()`. Limits are 128 complete rows, 256 KiB consumed input, 32 KiB per row, 4,096 chunks and five seconds for the body, with a 15-second route deadline. UTF-8 and JSON string escapes may span chunks. Only a complete validated row advances the cursor. Byte/row/deadline cutoff cancels the stream and reports `hasMore`; malformed or oversized rows retain the last validated cursor and provide a fixed Coder fallback. An oversized first row cannot be skipped. Metadata verification and final actor authorization still apply to a returned prefix. Cancellation is itself bounded; timeout is not a claim that an underlying network operation was undone.

Raw output is returned only to the explicit detailed view and held one page at a time in browser memory. It never enters publication jobs/events, the safe progress terminal, notifications, agent tools, local storage or telemetry. The view renders escaped plain text, strips terminal controls, aborts on close/unmount, resets for task changes and clears when hidden or authorization fails. It has explicit page/refresh controls and no automatic polling. Provider output cannot create HTML, terminal links or navigation targets. A fixed Coder link is constructed from configured origin and validated stored names. Unattached/not-yet-created imports fall back to the Coder template catalog rather than inventing an attached version link.

The existing template list/detail pages mount the viewer only when the portable POST advertises the capability. A notification's `?publication=<UUID>` selects a read-only result view; opening it never publishes or retries a job. Node's existing CLI/raw SSE behavior is unchanged.

## Durable terminal notices

Migration `20261029180000_template_publication_notices` adds one owner/job/event-bound notice per terminal publication and an additive event identity index. Composite foreign keys bind the exact owner and same job's terminal event. Settlement writes job, event and notice in one transaction. Existing rows are not backfilled and SQL 27/28 remain unchanged.

The internal dispatcher is independently default-off (`HIVE_TEMPLATE_NOTIFICATION_DISPATCH_ENABLED`). It handles at most one notice per wake and 20 subscriptions. Claims use bounded `SKIP LOCKED`, a distinct holder/expiry lease (120 seconds), monotonic attempt fence and five total attempts. Pending retry time is separate from processing expiry. Acknowledgment validates the current holder/attempt/status/expiry, locks the current owner identity and checks the database clock again after writes before commit. A stale or late acknowledgment cannot retire a newer consumer's claim. Actor-origin/Coder-user changes suppress further dispatch; original session expiry alone does not suppress generic result notices.

Messages contain only the maintained template name, fixed result labels and a fixed job deep link. Held/unknown work says it needs review. The existing `template` preference and fetch/VAPID transport are reused; no Coder credential, authentication-service secret or application encryption key is needed. Gone subscriptions are removed only under the exact owner/id/endpoint. More than 20 subscriptions is a bounded failed delivery, not a silent partial success. Deployment VAPID keys stay server-side.

Push is at least once: timeout or lost delivery acknowledgment can leave a request in flight. Retries reuse the stable `hive-template-<job UUID>` tag and immutable result; no exactly-once external delivery is claimed. Failed/exhausted notices remain retained and do not alter the publication result. The new table follows existing server-owned tenancy (owner predicates/composite FKs); it introduces no caller-controlled RLS identity. Public privileges are revoked; an existing `hive_app_runtime` receives only SELECT/INSERT/UPDATE on this table, with DELETE/TRUNCATE/REFERENCES/TRIGGER revoked. Generic dispatch totals contain no job IDs or raw output.

The sender deadline propagates a real abort signal into the fetch transport. A bounded cancellation wrapper gives the shared VAPID helper a bodyless status response. After timeout the dispatcher still drains the **actual** sender promise before acknowledging or returning, including subscription/VAPID reads and any already-started expired-subscription deletion. A late result remains a retry; it cannot justify early context closure. Caller-owned database query/transaction deadlines bound normal driver work. An opaque callback that ignores cancellation and never settles keeps the invocation held rather than claiming to be drained. Tests prove this with deferred database work and an expired-subscription delete. These are database-lifetime guarantees, not native-writer quiescence or proof that an in-flight push was undone.

`role-baseline.json` records a separate read-only inspection of the existing isolated preview runtime: `hive_app_runtime` already has effective and direct DELETE permission on `push_subscriptions`, so the existing 404/410 cleanup contract needs no new permission. The preview also has DELETE grants on other old tables; this slice does not call that baseline globally DELETE-denied or change it. The new notice table independently revokes deletion/truncation. The fresh local grant fixture intentionally starts with only the new notice privileges; it is not a substitute for the old-table production-role baseline. No subscription was deleted and no grant changed by that read-only inspection.

## Evidence and limits

`template-publication-logs-local/` contains fresh schema-29 and populated 28→29 preservation evidence. The migration snapshot explicitly stops at 180000; concurrent policy migration 30 is excluded. The original draft trigger's SQL parse failure is retained at `/tmp/hive-template-notices-fixture-failed-sql.json`; the successful fresh fixture is separate and no applied checksum was rewritten.

Tests cover parser boundary/escape/size/deadline attacks, owner/source isolation, revocation during buffered reading, no raw persistence, explicit viewer/paging/reset behavior, atomic notice rollback, current account binding, real-clock lease expiry during SQL, restart/concurrent claims, bounded retries, template preference, subscription cap and least-privilege grants. Short bounded constructor timings are used only by internal tests; production wiring omits them and keeps the 120-second lease/30-second base backoff.

The actual local workerd proof uses a full generated Worker Prisma client against local PostgreSQL and synthetic auth/Coder bindings. It verifies an authenticated log read, oversized-row fallback without cursor advancement, no durable raw output and a metadata-only notice claim/ack with an injected sender. `--logs` records the committed canonical template revision and corrected directory-bearing archive. It does not claim actual provider extraction or real push delivery. Run `node deploy/cloudflare/jobs/run-local-publication.mjs --logs` with the recorded local fixture; no remote bindings are enabled.

Remaining activation gates include real authorized provider acceptance, browser-profile visual validation, old Node worker drain, aggregate jobs/subrequest budget review and scheduler/deployment approval. The per-notice cap does not promise a bound for unrelated simultaneously enabled jobs or shared-account charges. Parent-owned app/jobs wiring and flags remain separately reviewed.

Pinned reference: [Coder v2.38.4 log handler](https://github.com/coder/coder/blob/v2.38.4/coderd/provisionerjobs.go) implements the HTTP array/`after` path; [template-version logs](https://coder.com/docs/reference/api/templates#get-logs-by-template-version) documents the fixed provider endpoint.
