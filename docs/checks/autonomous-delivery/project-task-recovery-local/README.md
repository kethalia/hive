# Explicit owner recovery of blocked project tasks

The owner retry route uses signed `recovery-inspect` and `recovery-consume` host requests when guardian admission is enabled. It sends immutable request digests and identity only; recovery requests never contain the task prompt. The original encrypted intent remains the source for an absent task's later ordinary start.

Inspection saves a durable local input gate before asynchronous work. A missing task is recoverable only when no guardian admission, managed checkout/lease, native thread, or archived/idle controller history exists. An existing task must be blocked before its first prompt, retain the exact request and checkout identity, and prove empty native history when a native thread exists. Unknown history remains held. The outer's fresh signature binds the complete scope and inspection digest; normal enrollment verification checks the installed package, Coder build, runtime lifetime, and current authority.

Migration 44 adds bounded immutable recovery records. Authorization locks runtime then intent, rechecks repository policy and epic pause/build constraints, compares the exact microsecond intent version, and changes only that intent from blocked to queued (absent) or preparing (existing). Ciphertext is preserved. The normal reconciler cannot claim an intent with an active recovery. A grant expires within 60 seconds and within the runtime's already-existing authority deadline.

An existing host task saves the authorization and consuming state, obtains a fresh guardian fence, then saves the immutable consume receipt before scheduling. Every prepare/checkout/native/fence during consume carries the exact recovery ID and authorization digest. The server checks the active authorization, task version and deadline under the runtime lock, including a final database-clock expiry check before commit. Ordinary operations cannot use an active recovery. The outer independently refuses producer metadata and native launch while the local recovery is consuming. A consumed grant provides no additional authority: normal runtime, registration, intent and package checks still apply.

A lost consume response replays the saved receipt without scheduling again. A server crash after authorization resumes the same durable grant; a host restart after the receipt retains it. A crash or uncertain fence before the receipt, an expired authorization, changed facts, newer task, unavailable empty-thread history, or archived/idle history stays held. This slice intentionally provides no automatic supersession for an ambiguous recovery attempt and no blanket blocked-runtime bypass. Old installed packages are not hot-adopted; their held state remains untouched.

Validation uses isolated loopback PostgreSQL, canonical host modules and their packaged transforms. It covers unchanged ciphertext and queued re-entry, exact CAS/policy rollback, claim exclusion, canceled and expired grants, immutable SQL history, delayed-SQL expiry rollback, real guardian fence composition, lost responses, restart receipt replay, prompt-free owner routing, and the independent outer producer gate. No provider, workspace, deployment, or Git operations are part of this evidence.
